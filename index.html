Generator system

The number of generators can be configured independently of the number of spawn points. For example, with 40 spawn points and a limit of 4 generators, the system selects 4 random locations without duplicates. Each generator is assigned one of three minigames: memorizing a sequence, navigating a maze, or connecting wires. The first three generators always receive different minigames to prevent repetition, while the fourth and any additional generators receive a random one. The system can also be expanded with new minigames.

Description & video

The number of generators can be configured independently of the number of spawn points. For example, with 40 spawn points and a limit of 4 generators, the system selects 4 random locations without duplicates. Each generator is assigned one of three minigames: memorizing a sequence, navigating a maze, or connecting wires. The first three generators always receive different minigames to prevent repetition, while the fourth and any additional generators receive a random one. The system can also be expanded with new minigames.

Up to three players can repair the same generator simultaneously from different sides, with each repair spot limited to one player. All core game logic is handled by the server, including distance checks, character state validation, repair spot availability, completion time verification, and request rate limiting. This helps protect the system against forged requests and invalid client actions.

Repair automatically stops if a player dies, leaves the game, or moves away from the generator. Each generator maintains its own state, tracks players currently repairing it, and monitors repair completion.

Systems

M1 combat system

A combat system with a modular architecture, server-side damage handling, combo processing, and hit detection. Supports PC, mobile devices, and gamepads with customizable controls. The system features a four-hit combo with three different finishers: standard knockback, Downslam, and Uppercut. During the first three hits, the character automatically moves closer to the opponent, maintaining combat flow and allowing combos to continue smoothly. A directional blocking system is implemented with a default protection angle of 110°, which can be adjusted in the settings. Blocking protects against frontal attacks, while attacks from behind and above bypass it. All major combat parameters are stored in a ModuleScript, allowing damage, hitbox sizes, knockback force, dash settings, blocking angles, and other values to be adjusted without modifying the core logic. The server handles hit validation, damage calculations, and combat actions, while the client manages animations, visual effects, and movement to ensure smooth and responsive gameplay.

Server logic

Item collection & economy

A trash collection system with a modular architecture, server-side security, and a fully integrated economy. Items spawn randomly across the map with different rarities and individual spawn chances. After being collected, trash automatically respawns every 15–30 seconds. Spawn intervals, item rarities, and individual spawn probabilities can all be configured through ModuleScripts. The system features dynamic pricing that scales with the player's level and progression, increasing item values with a multiplier ranging from 1.1x to 2x. The server validates player balances, item prices, collection speed, and player actions, protecting the economy against forged requests and attempts to manipulate data. ProfileStore is used to save player progress, including currency, inventory, and other profile data. The system includes separate APIs for inventory management, allowing items to be added, removed, transferred, or the entire inventory to be cleared. A dedicated economy API handles coins, stamina, stamina regeneration, and other profile resources. Core settings, including prices, item properties, spawn probabilities, and economy configurations, are organized into ModuleScripts, making the system easy to customize, maintain, and expand
